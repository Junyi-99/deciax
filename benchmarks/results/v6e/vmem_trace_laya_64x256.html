VMEM occupancy and HBM traffic, one fused forward (64 rows x 256 tokens, TPU v6 lite)

So what: the forward runs 30 Pallas kernels (one per layer) in 26.8 ms; the kernels hold 99% of the time. Peak VMEM is 45 MB of 128 MiB (layer_gated_gelu_w64: the four resident weight matrices 24 MB, the qkv / att scratch of one grid step 4 MB, the double-buffered x / x' blocks 8 MB, and 9 MB of body temporaries: one head's S x S scores and probabilities, the MLP hidden of one row block). VMEM does not grow with the batch: a grid step holds nseq = 2 whole sequences (tm = 512 rows) and a bigger batch only adds grid steps; the sequence length sets the S x S scores and, through tm = nseq * S, nothing else up to S = 512. HBM traffic is 5.6 GB per call (209 GB/s average): per encoder layer only the residual stream in and out (134 MB) and the weights (25 MB); every intermediate of the layer, including the qkv projection and the attention output that the three-kernel path wrote to HBM, stays in VMEM.

Per kernel: every block, scratch buffer and on-chip temporary of one grid step

Blocks are the operands the Pallas pipeline moves between HBM and VMEM per grid step. Blocks with a constant index (weights, norm vectors, biases, cos / sin) are fetched once and, from the measured numbers, kept in a single buffer; blocks whose index changes (rows, q / k / v) are double-buffered so the next step's DMA overlaps this step's compute. Temporaries = measured - blocks - scratch; Mosaic does not expose its allocation of them.

Around the kernels XLA runs 438 async copy / slice ops that prefetch kernel operands into VMEM (memory space S(1)) ahead of each custom call; their bytes are the same weight reads the BlockSpec accounting counts and are not added to the HBM total. The remaining 111 XLA ops (embedding gather, embedding / final norms, type_emb add, scorer) take 0.37 ms and move 826 MB.

An encoder layer now moves about 159 MB through HBM (x in, x' out, mask, weights) against about 495 MB with three kernels (qkv and att written and read back, the residual read twice). The single-pass attention keeps one head's S x S scores (0.2 MB fp32) in VMEM; above S = 512 the scores and the sequence-sized row block stop fitting next to the weights and the model falls back to norm_linear -> flash_attention -> out_mlp (run this script with --seq 1024 for that page).
