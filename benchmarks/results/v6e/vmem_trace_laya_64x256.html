VMEM occupancy and HBM traffic, one fused forward (64 rows x 256 tokens, TPU v6 lite)

So what: the forward runs 90 Pallas kernels in 27.9 ms; the kernels hold 99% of the time. Peak VMEM is 36 MB of 128 MiB (out_mlp: 36 MB = the three resident weight matrices, 18 MB, plus double-buffered row blocks and the fp32 MLP hidden of one row block); the kernels never come near the 96 MB limit, so there is headroom for bigger row blocks or a one-kernel-per-layer design at this sequence length. HBM traffic is 15.7 GB per call (562 GB/s average); every per-token intermediate of a layer stays in VMEM, what still crosses HBM is the three cross-kernel tensors per layer (qkv, att, the residual stream) and the weights.

Blocks: the "if all double-buffered" column assumes two buffers per input / output block; the measured numbers come out below it for norm_linear and out_mlp, so the pipeline keeps a single buffer for the weights whose block index never changes (the temporaries column goes negative by about one copy of the weights). Temporaries = measured - blocks - scratch is a residual: Mosaic does not expose its allocation of the body's live values (fp32 matmul results, LayerNorm intermediates, scores and probabilities, the MLP hidden).

Around the kernels XLA runs 736 async copy / slice ops that prefetch kernel operands (weights, norm vectors, biases) into VMEM (memory space S(1)) ahead of each custom call, so part of a kernel's operand set is already resident when it starts; their bytes are the same weight reads the BlockSpec accounting counts and are not added to the HBM total. The remaining 161 XLA ops (embedding gather, embedding / final norms, type_emb add, scorer) take 0.37 ms and move 828 MB.

At seq 256, one kernel per layer per sequence (grid over sequences, all heads in VMEM) would need about 38 MB of VMEM for its live values plus weights (residual, qkv, all scores, the MLP hidden, the four weight matrices): it fits in 128 MiB up to about seq 512 and would remove the qkv / att round trips and the second residual read, i.e. ~336 MB of the ~495 MB a layer moves now. Beyond that the attention must stay a separate flash kernel.
